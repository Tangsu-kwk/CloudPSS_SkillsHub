# CloudPSS Diagram Modeling（识图建模）

将用户的图片与参数材料转为可打开、可计算、可核对的模型。以材料解释、连接规划、SDK 构建、运行诊断为一条流程；复用 SDK 能力，避免每个模型重新开发工具。

## 工作边界

- 在调用者自己的 SDK Model 中创建、修改和检查；运行不依赖浏览器、MCP 转发或人工导出。公开 GraphQL 与官方 SDK 可用于鉴权、元件定义、保存、计算和结果接收。
- “从空白创建”使用空白项目工厂，逐个添加实例和连接。若任务评价识图能力，设计来源限于用户给定材料和公开元件定义；不读取参考项目的 cells、历史快照或重建配方。引入用户授权的参考前冻结首次独立构建及检查结果，参考辅助修正另记阶段和来源，不计为首次识图正确。
- 图片说明连接与方向，表格提供参数、信号和实例身份；两者冲突时先定位冲突，不默默择一。库默认值不是用户给定值，工程假设也不是图片事实。
- 潮流和暂态是两项独立验收。模型不支持某种计算时，说明缺少的元件、参数或初始化条件并提出具体解决路径；不把不适用记为成功，也不为跑通擅改模型性质。
- 按已有授权执行保存与计算，不反复确认。创建 skill 本身不授权操作云端；任务预算、目标 RID 和覆盖范围沿用当前任务约定。

## 先确定材料是否足以建模和计算

一次读取材料，形成紧凑清单，不为格式齐全而制造额外文档。检查：

| 材料 | 要解决的问题 |
| --- | --- |
| 主回路及控制图 | 元件、支路与公共节点，信号方向，控制闭环，跨图命名引用，旋转和镜像 |
| 元件参数表 | 实例标识、定义 RID 或库类型、参数键和值、单位、引脚绑定、动态端口配置；位置若已给出则复用 |
| 项目参数和工况 | 全局变量、事件时刻与幅值、初始值、参数方案；补查表格表达式引用的项目参数 |
| 计算与验收设置 | 潮流求解条件；暂态起止时间、积分步长、输出采样率、初始化方式、观察量及基准 |

区分“照图复现”与“满足运行目标”：前者出现疑似原图错误也不能悄悄修掉，后者在授权范围内修正并记录设计变化。缺少影响连接、物理参数或可比性的输入时，集中提出必要澄清，同时推进独立部分。经用户允许可用默认值或工程假设时，标明来源与影响，不通过调参掩盖读图错误。

关键字段需确认实际有值，而不只是存在列名。区分未提供、明确空字符串、库默认值及参数方案覆盖；记录有效值或表达式、单位和来源位置。默认值可在有依据或已获授权时使用，不把它当作材料事实；缺少关键参数时先完成可确定部分，不猜值反复试算。每次在 `工作区/outputs/<本次任务名>/` 创建独立任务目录。材料冲突、决策、通道映射、实际工况和验收结论集中记入 `task_record.md`；连接依据放入 `plan.json` 的 `evidence`，影响计算的疑点保留在 `unresolved`，不依赖会话记忆。

## 从材料得到连接计划

先读 [执行入口与计划格式](references/sdk-workflow.md)。使用 `scripts/model_pipeline.py doctor` 确认解释器，再调用 `import-table`；默认复用入口，不现场重写表格解析和 SDK 构建脚本。仅在入口不支持所需语义或给出明确错误时读取相应源码、补能力并验证。SDK wheel 位于 `assets/sdk/`，执行入口位于 `scripts/`，可随 Skill 搬迁。先用 `doctor` 检查依赖，在线调用前用 `doctor --check-auth` 检查配置；缺项按 reference 安装到独立环境，凭据由用户环境提供。

1. 按主回路、控制、量测输出等实际区域识别实例。为每个实例分配本次稳定的逻辑标识，关联表格行与图片区域；不要仅用不唯一的名称匹配。
2. 对表格涉及的定义 RID 去重，一次获取并缓存参数、pins 和 graphic。在已知类型集合中解决问题，不先遍历整个库。公开定义有歧义时针对缺失项查询。
3. 按列语义读取表格，不假定固定列号、工作表顺序或起始行。保留数字、布尔、枚举、空值和表达式的区别；不执行表格中不受信任的代码。仅对材料要求的参数做明确的单位换算。
4. 将图形端子对应到库端口 key，分别记录电气网络与有向信号连接。旋转、镜像只改变显示位置，不自动证明端口极性或测量正方向；对两端物理含义单独核对。
5. 用局部放大解决接点、交叉、支路和箭头歧义。名称相同的信号需核对生产者、消费者与维度；动态端口由参数生成，使用实际生成的端口身份，不猜编号。

编写连接计划前，阅读 [实例身份、量测方向与输出绑定核对](references/connection-review.md) 的适用部分。重点是：

| 元件类别 | 要核对的具体语义 |
| --- | --- |
| 同型控制元件 | 按输入来源、输出去向和关键参数区分身份；加减法器逐项核对正负号与权重，比较器／选择器／滞环核对条件，PI／坐标变换按定义核对方向和轴序 |
| 电流表、电压表 | **注意量测极性：过去多轮建模测试中，量测方向与端口对应曾多次出错。** 逐个核对图片箭头或正负号、定义端口、实际节点及正读数对应的方向；电压表区分单端参考地与两端差分，旋转／镜像后仍需对应 port key |
| 示波器、To Scope、输出通道 | 从输入追溯实际生产者，区分显示名、信号标签和测点；检查中间缩放、单位、相别与分量顺序，不能凭名称猜绑定 |
| 桥臂、相序接口、通道合并/分解器 | 相别、门极定义和通道行序的对应；不能仅凭上下排列推断互补关系或顺序。动态表解析、行字段映射和生成端口身份按 [执行说明](references/sdk-workflow.md#动态表适配) 核对 |

直接输出符合 reference 格式的 JSON 连接计划，至少能回答“哪个实例的哪个端口接到哪里、依据哪张图”。实例、端口及连接已明确的区域先构建，不等全部区域的长篇分析；边界信号和未确认连接保留为疑问。局部计划必须标明覆盖范围，不能冒充完整模型。按电气公共节点组织分支，避免视觉上线条相交就当作相连。

对涉及多个站点或设备类型的图纸，构建前先确认交付用途和模型粒度，按分区批量核对选型、公共节点和相对方位。按 [材料分项与设备选型](references/connection-review.md#材料分项与设备选型) 记录冲突和等值范围。先建计划中的实例，再按已核对的端点接线；跨区连接在总计划中保留两端身份。

## 使用 SDK 构建与静态校对

优先执行 reference 中的 `build`，每次使用新输出目录；它只构建空白内存模型并本地检查，不保存、不计算。报告同时给出潮流预检（`preflight`）与布局审计（`layout`）：前者核对节点—母线绑定、分区电压参考、限值与线路单位量级，后者核对位置齐全与符号外框重叠。缺位置、预检出错即为 `issues`；重叠默认只记录，交付图纸加 `--strict-layout` 升级为失败。判定细节见 [潮流提交前核对](references/diagnosis.md#潮流提交前核对) 与 [图面布局](references/sdk-workflow.md#图面布局)。

- 将识别出的实例、参数、连接和方案作为计划数据，复用通用构建入口。先项目参数与方案，再元件、连接与输出引用；缓存库定义，避免为每个实例重复联网。参数修正保留依据；转换和覆盖分别进入报告。
- 从空白创建，使用 SDK 添加接口取得真实实例 ID，建立逻辑标识到 ID 的映射。图纸位置来自材料或清晰的分区布局；初期先保证可读、可连，不把精细美化放在电气诊断之前。
- 参数转换按公开类型处理，保留表达式 source、动态表行身份及信号绑定。旧字段或库定义差异单列，不无声丢弃，也不把未知字段当成已生效。
- 按实例身份核对材料覆盖，列出已构建、遗漏、明确排除及新增实例；排除项说明依据，不靠数量相同证明完整，也不把表格残留强行实例化。校对参数和表达式、引用映射、有效端口、连接网络及方向；端口都有边不代表接对。
- 局部构建另列裁剪边界的端口或公共节点，保留原检查结果；只将有图片依据的边界问题判为预期，新增问题仍需处理。无报错也要核对边界覆盖，因为漏掉一条外接支路未必产生悬空；正反输出顺序、量测方向需与图片单独比对。
- 保存可计算版本前留本地快照。新 RID 先检查占用；已有项目覆盖须符合授权。保存后读回核对结构、参数、方案、定义身份及必要依赖/元数据，区分预期规范化和实际丢失，提供 SimStudio 链接。定义可获取不等于项目可解析；没有独立界面观测时不声称网页外观验收通过。

## 必做的项目级模型检查（网页 Ctrl+M 对应流程）

首次整体模型构建完成后，必须主动执行 SDK 的 `project_check.run_check`，不能只用 `build` 的 `static_clean` 或直接提交仿真代替。按 [项目级检查与报错闭环](references/sdk-workflow.md#项目级检查与报错闭环) 加载检查环境并保留完整报告；当前 SDK 尚未完全复现网页 Ctrl+M 的检查范围，调用成功不代表网页检查已通过。

- 阅读全部 error、warning 及 `checked_groups / pending_groups / pending_details / limitations / complete`。按根因归类并定位到元件、参数或连接，不忽略首次检查的大量报错，也不通过过滤级别、删掉问题元件或缩减检查范围取得零报错。
- 对每类问题记录处理结果：修复、依据明确的预期现象、或尚未解决；warning 也需说明影响。修复后重新检查，保留首次与最终报告及剩余问题。保存后对读回模型再检查；后续电气、参数或方案变化需重查受影响项。
- 未解决的 error，以及影响本次计算的缺失检查输入，须先处理，不能继续提交计算并宣称完成。检查异常不按空问题列表处理。`complete:false` 说明尚不能宣称与网页检查全面等价；结合具体未覆盖项判断影响，不能默默跳过，也不能仅凭该标记否定已完成的局部检查。
- 独立 SDK 工作流不依赖浏览器按快捷键或 MCP 转发。若用户另行提供网页检查结果，应逐项追踪本地与网页的差异；尚未消除的网页报错不能被本地报告覆盖。模型检查通过后仍需进行物理行为与仿真验收。

使用 `project_task.py check` 保存随包项目检查与官方 CloudPSS 5.0.10 检查报告；`save` 与 `run` 在写请求前同时执行预检与布局审计，任一为 `issues` 即中止并保留证据。官方检查发现明确错误时先修复；检查覆盖不足时，按报告定位受影响端口，用随包检查及端口证据复核。最终按图交付前核对 [图面布局](references/sdk-workflow.md#图面布局)。

## 潮流与暂态验证

按模型能力和用户要求选择顺序；需要潮流初始化暂态时先处理潮流，不能将某个案例的顺序变成所有模型的硬要求。

建模结论以实际计算为据：按用户要求与模型能力，用潮流或电磁暂态完成数值验证并在真实任务结果上核对。只做到静态检查、项目级检查或图纸审计时，如实说明尚未做数值验证，不把检查通过当作运行正确。

- **潮流**：按所选函数建立方案，并在提交前执行 [潮流预检](references/diagnosis.md#潮流提交前核对)。验收求解收敛、数值有限、运行点及功率平衡。缺潮流母线或只有开关控制模型时，先确认是否建立适用于当前目标的等值。
- **暂态**：确认初始条件、控制与开关采样、事件、求解步长、输出频率和量测单位。输出频率与积分步长分别设置。若需回写潮流结果或载入快照，验证 SDK 已实际应用；不假定潮流成功自动完成初始化。
- 优先用覆盖启动或可疑事件的诊断窗口检查关键量，再运行约定的完整工况。短窗口不替代完整事件验收；不为每条日志或绘图缺失重新提交任务。
- 运行前列“验收目标 → 观察量及绑定对象/测点/单位 → 工况窗口与判据 → 证据缺口”。判据依据材料、额定值或任务目标，不套用固定电压范围、平衡度或调制阈值；故障、启动和切换窗口分别判断。仅为缺口增加观测量，不默认复制历史诊断通道。
- 提交前核对真正使用的参数／计算方案、起止时间、积分步长、输出采样率和通道；未指定项说明默认值依据。将任务 ID 与实际参数记入 `工作区/outputs/<本次任务名>/task_record.md`，报告以实际工况为准，不符时不能作为指定工况验收。
- 同时检查任务身份、实际输入 revision 与方案、编译／求解日志和结果流完整性。静态检查通过但编译失败时仍需核对有效端口、信号来源和绑定；修复后读后续编译结果，不把首批报错消失当作全部修复。异常时读 [诊断与恢复](references/diagnosis.md)。
- 按 [任务目标验收](references/diagnosis.md#按任务目标验收) 检查适用的额定量级、功率平衡、控制跟随或开关关系；判据有材料／定义／推导依据，不自定阈值。将目标、观察量、判据、实际结果及未确认项记入 `task_record.md`；任务成功或波形稳定不单独证明正确。
- 用户提供基准或明确要求对照时，按 [诊断与恢复](references/diagnosis.md#基准差异的处理) 核对工况、通道含义、单位、时间和长度，再比较全程、事件段及稳态段。原要求与参考冲突时，保留原工况验收；改事件、模式、初始化或求解设置后的实验单独报告，不能替代原任务。

## 减少返工并记录过程

每个任务保留紧凑的材料索引、参数来源、实例映射、检查结果、修改记录与任务回执，优先复用已有输出字段，缺项合并进本次任务记录而不重复建文档。首次构建和阶段快照不覆盖；电气、参数、工况变化重做受影响检查和计算，纯显示变化复查图纸；未知副作用不视为纯显示改动。

用实测起止时间区分材料理解、库查询、连接规划、SDK 构建/检查、结果诊断和返工，平台排队与求解等待单列。沿用构建报告的机械分段计时，补记读材料开始、首次整体静态通过及首次业务验收通过的时间和重试原因。等待仅写身份及紧凑进度，阶段结束或恢复时落盘完整结果。不能靠文件修改时间或脚本重放时间推算识图成本，也不预先承诺固定分钟数。

交付说明创建内容、修正及依据、剩余问题、项目/任务身份和分阶段耗时。分开报告“模型已构建”“任务已完成”“约定业务验收通过”“与基准在指定容差内一致”，附对应证据与检查覆盖；非零残差不称逐位一致。无基准仍可完成约定业务验收，但不能宣称参考等效。记录实际模型档位与缓存请求情况，不把后期参考辅助修正的成功算成首次独立构建成功。

## 已有结果、指定方案运行与批量工况

- 已有任务的结果与指标：`scripts/result_metrics.py --job-id <ID> --metrics <定义.json> --out <目录>`。产物为 `result.json`、`metrics.csv`、`waveforms/<通道>.csv`。任务未成功、结果流未正常结束或未取得结果时只出诊断，指标表仅保留表头，不把该次读取计为成功。通道绑定按测点核对，缺失时该行留空并说明缺项；判据由用户给出，未给时结论为「未判定」。
- 指定方案单次运行：`scripts/run_selected.py --rid <RID> --config <名称> --job <名称> --out <目录>`。方案名无法唯一匹配时在提交前返回候选或不存在原因，不发出任何写请求；提交前依次核对预检、布局与官方检查，回执记录方案名与索引、`revision_hash`、提交参数摘要和 `jobId`。
- 批量工况：`scripts/batch_run.py`，逐项调用 `ScenarioSet.build()`，失败按工况隔离并记录字段与原因；同一预检与检查在每项提交前执行，`batch_manifest.json` 逐项落盘，已有 `jobId` 只查询终态，提交结果不明标「待核对」且不自动重提。
- 方案列表：`scripts/scenario_select.py --rid <RID> --list`，读取参数方案与计算方案的名称和索引。已有工作副本时，方案列表和单次运行都可用 `--document <模型.json>` 代替 `--rid`。

指标定义为 `{"metrics":[{"name":"指标名","channel":"原通道名","quantity":"peak_abs 或 rms","window":{"start":0,"end":1}}]}`。全程可省略 `window`。同名通道需给出 `plot`。单位沿用来源；明确授权换算时记录目标 `unit`、`unit_basis: "声明换算"` 和 `scale`。会话已交接同一任务的归档时，可用 `--records <SDK归档>`。

批量调用传 `--rid <RID> --config <名称> --job <名称> --spec <工况.json> --out <目录>`。清单格式为 `{"scenarios":[{"name":"工况名","patches":{"实际实例ID":{"参数键":数值}}}]}`。续跑同批使用原清单和 `--resume`，先回读已有任务。仅需处理结果或运行时，直接使用本节入口。
