# 实例身份、量测方向与输出绑定核对

编写连接计划时，阅读本次涉及的元件类别；与材料或定义的冲突按下述位置落盘。

## 同型元件的身份、符号与连接核对

**同型元件按功能区分，符号与实际连接一起核对。**

对图片中多个外观相似的元件，结合输入来源、输出去向和关键参数确认其身份；名称、位置和创建顺序只能辅助匹配。

- **加减法器**：逐个核对图片中各输入的正负号、对应权重参数和实际输入信号，简记关系式，例如“误差＝给定－测量”。权重不止 ±1 时，保留实际系数。
- **比较器、选择器、滞环控制器**：核对比较方向、阈值或切换条件，以及各输入、正反输出的实际去向。
- **PI 控制器、坐标变换模块**：按公开定义核对实际存在的方向、模式和轴序参数，并确认对应输入输出；不假定所有类型都具有同一种极性设置。

图片符号可能由参数条件渲染，必要时查看公开定义中的图形条件，确认符号对应哪个参数。

每次建模在工作区内创建独立目录 `outputs/<本次任务名>/`。核对结果简记于同目录 `plan.json` 中对应实例或连接的 `evidence` 字段，不为每个元件另建文档。

图片与表格冲突时，将具体实例、冲突字段、图片位置、表格单元格及处理状态，写入 `工作区/outputs/<本次任务名>/task_record.md`。不因某种接法“更合理”或波形更稳定就自行覆盖材料。解决后补充处理依据，并同步更新同目录的 `plan.json`；影响计算且尚未解决的冲突保留在计划的 `unresolved` 中。

## 材料分项与设备选型

1. 按站点、设备类型和总量分别对照图与明细表，定位异常到图片区域或表格行列。线路同时核对两端身份、电压等级和回数。总量一致时仍须处理分项冲突。
2. 在现有计划证据中记录「图纸对象 → 定义 RID → 计算用途 → 有效端口」。合并设备时保留成员及分项。采用等值时说明保留的行为、适用工况和省略的控制或设备特性。
3. 根据实际方案和实例参数生成有效端口。区分显式连线端口和以参数绑定的命名信号，按定义确认端口支持的绑定方式，核对实际生产者、消费者和维度。名字相同或画面相邻只用于定位候选。

## 电流表、电压表的方向与极性核对

**注意量测极性：过去多轮建模测试中，量测方向与端口对应曾多次出错。** 这类错误可能通过静态检查，并导致反馈反号或输出量整体反号，因此需要逐个核对，不能仅凭检查通过或波形稳定判断正确。

对本次模型中的电流表、电压表逐个核对，不能只确认图形朝向：

- **电流表**：辨认图片箭头，结合公开定义确认测量正方向，写明两端分别连接哪个节点，以及电流从哪个节点流向哪个节点时读数为正。
- **电压表**：结合图片正负号和公开定义，确认是两端差分测量还是相对参考地的单端测量，写明被测节点、参考节点及电压正方向。不按外观自行增加端口或接地元件。
- **旋转或镜像的实例**：将变换后的图形端子对应到定义端口 key，再核对实际接线；不能将视觉位置直接当作正负端。

将“图片方向依据 → 定义端口 → 实际节点 → 测量正方向”简记于 `工作区/outputs/<本次任务名>/plan.json` 中对应实例或连接的 `evidence` 字段。节点名称沿用连接计划中的命名。

图片或公开定义不足以确定方向，或图片与表格存在冲突时，将具体实例、疑点、图片位置、表格单元格（如涉及）及处理状态，写入 `工作区/outputs/<本次任务名>/task_record.md`；影响计算且尚未解决的问题保留在同目录 `plan.json` 的 `unresolved` 中。解决后补充处理依据，并同步更新计划。

## 输出通道的信号绑定与单位核对

**输出通道必须追溯到实际测点，不能根据通道名称猜测信号来源。**

对图片中的示波器、To Scope 和其他输出通道，逐个核对以下关系：

- **通道输入**：从图片中通道输入端的连线或信号标签开始，向前追踪生产者。通道显示名称与输入信号名称不一定相同，不能因为名称相近就认定绑定正确。
- **实际测点**：确认信号来自哪个元件、哪个端口或内部量测，测量的是哪两个节点之间的电压、哪条支路的电流，或哪个控制变量。区分模块内部量测与外部表计，不因它们都表示“电压”或“电流”就互相替代。
- **缩放与单位**：检查测点到通道之间是否经过增益、标幺换算、单位换算或其他处理，区分原始量与处理后的量。不能只修改通道名称或显示单位，而不修改实际绑定。
- **分量与顺序**：多维信号需核对维度、相别及分量顺序；经过通道合并或分解时，确认每一分量实际进入哪个输出。

按公开定义和 SDK 接口，将信号来源及消费端绑定写入正确字段；区分元件参数 `args`、引脚绑定 `pins` 和显式连线，不根据图形上出现一个端子就猜测连接方式。

在 `工作区/outputs/<本次任务名>/task_record.md` 中简记“通道 → 实际测点或信号来源 → 中间处理 → 分量与单位”，并将实际参数、绑定和连接同步落实到同目录的 `plan.json`。已有输出映射表时直接补充，不重复建表。

仿真后核对实际返回的曲线与上述映射是否一致。不能仅按曲线名称或返回顺序配对；无法确认来源的曲线标为未确认，不用于支撑对应业务结论。

材料缺失或冲突的记录与处理沿用前两条。
