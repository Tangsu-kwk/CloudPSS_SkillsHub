# 建模故障的诊断与恢复

用于构建、检查或仿真出现问题时。按证据定位层次，不累积某个案例的特定元件禁令。

## 先分层，再选择检查

| 现象所在层 | 优先取得的证据 | 处理方向 |
| --- | --- | --- |
| 材料理解 | 图片局部、参数表原单元格、公开参数与端口定义 | 区分缺信息、材料冲突和误读。保留尚未证实的解释，不自动补成库默认值 |
| SDK 构建 | 失败操作、输入类型、元件身份、模型修改前后差异、异常栈 | 区分调用错误和 SDK 缺陷；失败可能消耗 ID 或部分修改，核对后从本地快照恢复 |
| 参数与表达式 | 参数键、表达式 source、项目变量及当前方案、类型与单位 | 查引用、类型转换、有效条件、循环依赖；不靠改控制增益掩盖引用错误 |
| 拓扑与信号 | 实际有效端口、边端点、网络节点、信号生产者和消费者、维度 | 区分悬空、错连、维度不符、重复驱动、正方向错误。非空 pins 不是电气连通证明 |
| 保存与运行输入 | 保存回执、读回内容、任务 revision、参数方案、函数和实际参数 | 先证明跑的是哪个版本；读回或等待失败先恢复，不盲目保存和重复运行 |
| 计算服务 | 队列、权限、资源、编译及求解日志、任务状态、流完整性 | 区分传输、排队、编译、求解和采集失败；不要将平台故障当作电路错误 |
| 物理及控制行为 | 带单位和方向的关键量、事件前后窗口、必要中间信号 | 查量测正方向、控制误差符号、反馈路径、相位/通道顺序、初始化和采样；这些是调查候选，不是预定根因 |

## 静态检查通过但编译失败

按报错实例核对有效端口、信号来源及绑定方式，不能因为静态检查通过就排除连接问题。日志可能没有一次列出全部错误；修复首批报错后，继续读取后续编译结果，不能把首批错误消失当成全部修复。沿用已有检查报告、任务日志与 `工作区/outputs/<本次任务名>/task_record.md`，不新增专门记录。

## 用最少实验分辨原因

1. 保存当前模型、方案和已存在任务 ID。给出可检验假设及支持它的现象，避免同时修改接线、参数和求解设置。
2. 先利用静态记录和已完成任务。还缺观测时，在独立内存副本增加少量量测，选择覆盖异常发生时刻的短窗口；计算次数遵守用户预算。
3. 做最小可区分对照：改变一个候选原因或一组不可分的关联量，其他输入一致；记录修改、预期现象和实际结果。假设被否定则恢复副本，不把所有诊断通道与试验参数留在交付模型。
4. 基于证据修正。若修正会偏离用户指定图片、参数或运行目标，按现有授权处理必要澄清；已授权范围内不反复询问。标明“材料复现错误”还是“原材料设计变更”。
5. 对电气、控制、参数和方案的实际变更重跑受影响的检查，最后完成约定工况验证。诊断窗口正常不能替代完整验证。

静态无错而动态异常时，先看方向、幅值、单位、事件和初始值。电流表反号、比较器互补输出错序、反馈漏连都属于候选原因，但发散、三相不平衡或长期贴限幅不能唯一指向它们；参数、初始化与故障本身也可能导致这些现象。反转极性后变有界，只能支持假设，仍须用图片、定义和功率/方向约定确认，不能靠调参或“波形好转”确定正确接法。

连续实验未增加可区分证据时，暂停改模型，回查材料缺项、实际输入版本、测点和单位；写明需要哪项新证据再推进。不将每轮尝试都永久叠加到交付模型，也不为所有模型固定执行极性反转实验。

## 潮流提交前核对

- 按实际计算函数、参数方案和元件定义，核对参与求解的设备接到了有效母线、每个待求解电气分区有适用平衡参考、同母线节点模型组合受支持。检查启用的节点类型及上下限，缺值或工程假设记录到现有任务记录。
- 对依赖长度或基值的参数，记录原量、定义单位、折算及写入值。线路的全长阻抗、单位长度阻抗、容性电抗和电纳分别按字段定义处理。
- 对多设备汇集或等值，按实际工况回读各成员与聚合有功/无功，核对分项是否遗漏。计算后检查功率平衡与连续触限，将由假设限值主导的结论标明。

前三项中可离线判定的部分由 `scripts/preflight_checks.py --model <模型.json> --out <目录>/preflight.json` 执行，`project_task.py check/save/run` 与单次、批量运行入口在提交前自动调用，非 `clean` 时拦截：

| 检查码 | 触发条件 |
| --- | --- |
| `node_without_bus` / `island_without_reference` | 潮流节点模型没有母线邻居；分区内没有电压参考源 |
| `invalid_q_limits` / `missing_v_bounds` / `pv_without_voltage` | 上下限倒置、缺项，或 PV 节点没有 `pf_V` |
| `suspected_unit_mix` | 线路 `R1`／`Xl1`／`Xc1` 落在单位长度量级之外（例如把全长阻抗填进按 Length 折算的字段） |
| `capacity_mismatch` / `operating_point_differs` | 标签声明的 MW 与容量类参数不符（error）／与运行点不符（warning） |

报告中的 `line_unit_evidence` 与 `capacity_reconciliation` 保留逐实例的原量、折算和偏差，可直接抄入任务记录。该脚本只覆盖结构、限值与量级；收敛性、平衡和各成员实际注入仍需按上述三项在运行后核对。

## 按任务目标验收

**计算完成后，按用户目标和模型特点核验实际结果，不能仅凭任务成功或波形稳定宣称建模正确。**

运行前，根据材料和用户要求确定关键观察量及验收依据。例如：

- **电气运行**：检查电压、电流的量级与额定参数是否相符，以及适用的功率平衡、相序和三相对称关系。
- **闭环控制**：检查实际量是否按预期跟随给定，事件发生后响应方向是否正确，是否存在持续偏离或非预期饱和。
- **开关与多通道信号**：检查材料要求的门极顺序、互补关系和通道映射。

按模型实际涉及的内容选择判据，不要求每个模型执行全部检查。判据来自用户要求、材料、公开定义或明确说明的物理推导；无法确定的目标标为待确认，不自行编造阈值。

计算后检查日志、结果完整性，以及关键曲线的时间范围、采样情况和数值有限性，再核验上述业务目标。发现异常时，沿材料、参数、连接和信号绑定定位原因，不通过改动给定参数来掩盖问题。

在 `工作区/outputs/<本次任务名>/task_record.md` 中记录“验收目标 → 观察量 → 判据依据 → 实际结果 → 结论及未确认项”，引用对应任务日志和必要结果数据。

**用户提供基准，或任务明确要求对照时**，再核对双方工况、测点、单位和时间坐标，执行数值比较并保留可复核证据。没有基准时，可以完成有依据的业务验收，但不宣称“与标准波形一致”。

## 基准差异的处理

先核实基准的项目/任务身份、实际输入和输出设置，区分“同族模型”“参考任务输入”和“参考波形”；三者不能直接互相替代。条件可追溯时不必每次重跑基准；不明时列出待确认项。波形可提示事件假设，但无明显扰动不能证明没有模式切换，单凭拟合也不能唯一确定缺失参数。

比较契约：

1. 按物理量、绑定对象/测点、方向、相序和单位建立一一映射。图分组和曲线名辅助定位，不必为比较而改模型的显示分组。缺失或额外曲线单列。
2. 核对每条曲线的数据有限性、时间范围、点数与时间坐标；时间重复或回退需先解释。不能用 `min(len(a), len(b))` 截断后宣称完整一致。输出采样不足以分辨目标动态时标明局限；不以固定开关频率倍数保证无混叠。
3. 统一事件、参数方案、初始化、求解和采样设置。需要单位换算、重采样或插值时保留原数据并说明方法与影响；不得静默移时、缩放或删点。
4. 同时报全程、事件段和稳态段的最大绝对差与 RMS 差，按需要补相量/相对误差。窗口和容差依据任务确定；相对误差分母近零时单独处理。不能剔除启动/切换段后宣称全程一致。
5. 数值附原始单位和物理尺度；工程单位换算保留倍率。非零误差只能按明确容差判断数值接近，不能称“逐位一致”，也不由某个百分比直接判定接线错误。

原任务与基准工况冲突时分别验收，改变模式或事件来匹配参考只算对照实验；短窗口、仅稳态或仅部分通道通过需明确范围。若任务只要求按材料运行，没有基准，不擅自读取受限参考结构，也不将缺少基准视为不能进行业务验收。

## 恢复与停止条件

- 结果读取超时：保留任务身份，查询状态与已接收消息；确认结果是否完整后继续采集。提交结果未知时先查已创建任务，不通过重试制造重复计算。
- 鉴权、权限、定义不可访问或检查器不支持：保留本地可重放模型和明确的失败阶段，提出具体缺项与解决路径，继续无依赖部分；不能伪造空检查或无条件跳过预检。
- 缺少决定物理含义的输入、对照无法区分原因或达到任务预算：报告已有证据与最小下一步，不连续试错直到偶然成功。

修正记录应能串起：现象、假设、实验/依据、实际修改、对应任务、验证结果和剩余不确定项。阶段时间用实测记录；文件最后修改时间只作定位线索，不能换算为 Agent 操作耗时。
