# 数据来源与优先级

## 来源映射

按证据角色而非单纯按文件扩展名分类。

| 角色 | 常见文件 | 用途 |
| --- | --- | --- |
| 用户上下文 | 对话、需求说明 | 目标、读者、范围、语言、风格、输出路径 |
| CloudPSS 导出索引 | `simulation-results/<RID>/manifest.json` | 结果 RID、仿真类型、文件清单、图组标题和通道映射 |
| 主报告 | `.md`、`.html`、`.txt`、确认的报告文档 | 展示事实、既有结论、名称、窗口、面向读者的术语 |
| 结构化元数据 | `.json`、`.yaml`、`.xml` | 溯源、配置、标识符、字段结构 |
| 结果表 | `.csv`、`.xlsx`、`.tsv` | 详细数值表与比较 |
| 原始时间序列 | 单通道 CSV、测量导出 | 图表、采样/时间范围、数据现象 |
| 模型/配置 | 模型导出、参数文件 | 仅在相关时补充背景 |

## CloudPSS 结果导出

只有结果 RID 或本地缺少用户要求展示的波形时，在当前工作区运行 `python <Skill目录>/scripts/export-simulation-result.py --result-rid <RID> --token <TOKEN>`。脚本固定输出到 `simulation-results/<RID>/`：

- `manifest.json` 是唯一入口，所有数据文件按其中的相对路径定位。
- 潮流结果输出 `buses.csv` 和 `branches.csv`，作为结果表。
- 电磁暂态结果按图组输出 `plot_000.csv` 等文件，作为原始时间序列。
- Token 是必填输入。执行脚本前，Agent 在命令中显式引用 `CLOUDPSS_LOGIN_TOKEN` 和 `CLOUDPSS_TOKEN`，优先取 `CLOUDPSS_LOGIN_TOKEN`，为空时取 `CLOUDPSS_TOKEN`，并作为 `--token` 参数传入；脚本不读取环境变量。
- 两个候选变量均为空时停止导出，并提示“当前运行环境缺少 CloudPSS Token，无法导出仿真结果。”；Token 不得写入索引、CSV、报告或日志。
- 不要扫描或引用 `manifest.json` 未列出的同目录旧文件。
- 仅使用重导出数据计算的数值标为「按本次导出波形统计」，给出通道、单位、窗口和样点数。单位或工况没有证据时标明缺项。

## 短路分析产物交接

从已交接的结果目录定位 `<输出目录>/<任务ID>/analysis_result.json`、同目录原始波形，以及有则核对的 `<输出目录>/submission.json`。文件已单独归档时，按其实际路径传入。

```text
python <Skill目录>/scripts/read-short-circuit-evidence.py --analysis <analysis_result.json> --task-id <任务ID> --receipt <submission.json>
```

`--receipt` 可省略。工具依次查找分析文件同目录、上一级的 `submission.json`。若文件单独归档，或存在多个任务的回执，显式传入同一任务的回执。身份、运行记录或原始波形与分析指标冲突时，先核对输入。缺失原始波形时，已有指标仍可按分析结果展示，同时指出哪些图或复算证据缺失。等效电流标注为间接估算；只有对应估算数据可用于等效电流图。

- 工况、接法、运行版本、测点和指标取自同一任务的分析与回执。运行 revision 和工作副本的基线 revision 分别注明。只有端点、元件或量测定义支持时，才确认接地方式和通道相别。
- 中文或英文 HTML 报告在同一命令末尾加 `--html-table zh-CN` 或 `--html-table en`，将输出原样嵌入指标章节。构建后在该命令末尾再加 `--check-html report.html` 核对指标表。其他语言按 JSON 输出生成并逐项核验。保留 Markdown 中的术语和说明，涉及数值和取窗的正文与已核对的结构化证据一致。
- 波形使用工具定位的 CSV，按 `unit.effective_current_scale` 换算，并保留通道名和测点来源。故障窗图采用每路实际入选样点的边界，配置时间窗另行标明。额外导出的图组波形可作补充，原报告三项指标继续沿用原分析口径。
- 正文根据本次通道的峰值、RMS、波形特征与接线写结论。电流均值、阈值和衰减的表述按[短路电流波形](visualization-and-writing.md#短路电流波形)处理。涉及国标时沿用短路分析资料所列计算口径与适用条件。

## 优先级

1. 用用户上下文确定报告目的和表达方式。
2. 用主报告确定展示事实和报告文字基准。
3. 用 `manifest.json` 和其他结构化元数据补足缺失的结构或溯源信息。
4. 用结果表展示详细数值。
5. 用原始时间序列生成图表和现象分析。

已有结构化短路分析产物时，执行上节交接规则。其他报告中，若面向读者的事实在不同来源中冲突，以主报告为基准。若差异影响关键指标，在附录中简洁标注来源或分析范围。

## 主报告选择

优先选择具有清晰标题、模型/分析身份、已陈述指标、结论或结果表的报告。存在多个候选时，优先采用用户指定文件；否则选择其标识符与指标最能对应结构化文件的报告。

不得因模型导出文件更大或更详细而将其误当作主报告。

## 最小证据要求

- 存在主报告、同一任务的结构化分析或用户明确提供的事实集合时，才生成叙述性报告。
- 存在可用数值时间轴和至少一组数值序列时，才生成图表。
- 表头和行语义可识别时，才生成结果表。
- 关键证据不足时，先说明所需输入，不生成推测性报告。
