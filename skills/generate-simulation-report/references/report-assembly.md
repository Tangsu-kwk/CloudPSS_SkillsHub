# 动态报告编排

## 固定逻辑

按以下顺序组织工作：

```text
用户目标 -> 证据映射 -> 主要对象 -> 可用结果 -> 动态章节 -> 质量检查
```

## 中性报告骨架

仅包含有证据支撑的区块：

1. 报告头部：标题、分析对象、身份信息、生成信息。
2. 执行摘要：目的与最重要的已验证结果。
3. 结果总览：可用时展示简洁指标或比较。
4. 过程数据可视化：每组有效信号生成一个小节。
5. 结果表：可用时展示详细计算或测量结果。
6. 专项分析：仅在存在且可理解的领域指标时生成。
7. 结果讨论：由结果和图表支持的关系。
8. 结论：精炼的已验证发现。
9. 附录：来源映射、通道清单、分析设置和溯源。

不得仅因为此处列出就创建标题。

## 区块选择

- 读者需要精确的跨通道或跨案例数值时优先使用表格。
- 时间、趋势、顺序、分布或关联重要时优先使用图表。
- 主图配一段简短观察说明，不在正文重复罗列所有绘图数值。
- 辅助图仅在有助于解释主要对象时出现。
- 主报告术语清晰且面向读者时优先用于标题；否则使用“过程数据”“计算结果”“辅助指标”等中性标题。

## 独立 HTML

- 将图表数据嵌入唯一的 `report-chart-specs` JSON 脚本块；不得在报告中手写 Plotly 初始化调用，构建器负责注入固定渲染器。
- 在附录中包含来源和生成说明。
- 对长报告使用响应式布局、可读表格和稳定锚点。
- HTML 直接从磁盘打开时保持可用；不得依赖 `fetch()` 读取同目录 CSV。
